06 · 通用平台规划

同方向开源项目 · 第二轮清单

在第一轮 7 个仓库基础上补跑 20 组关键词（中英双语 + 主题检索）， 新验证 9 个真实仓库。本轮最重要的不是"又找到几个"，而是找到了一个架构级参照物， 以及三个正在被整个领域公认、而我们还没做的价值点。

检索日期 2026-10-10 方法 GitHub Search API（只读，未 clone 任何代码） 已落地 sort 链改写 assigner.py

一句话结论

第一轮我说"star 全 0~4 ⇒ 空白区"——这个判断只对了一半。 补跑后仍然没有 star 过百的同类项目，但出现了一个 MIT 协议、中文、133 个测试、带 GUI 和 exe 安装包的 同架构同行（medshift，医院科室排班）。它证明这条路走得通，也证明我们不能再靠"通用排班器"这个身份立足。

差异化只剩三块它能做、但它的场景不需要的：换届传承、跨机构版式（上传空表只填格）、 包干制 vs 轮值制的识别。这三块恰好都是我们已经踩过坑的。

02头号发现：medshift —— 我们 P1 的图纸，别人已经画好了

它是医院放射科排班器，v0.2 Beta，MIT，133 个 pytest 全绿， 有 medshift init my-dept 生成配置骨架、有 Flask GUI（同样监听 127.0.0.1）、 有 Inno Setup 打包的 Windows exe。逐条对照我们的 P1：

medshift 已有的它怎么做我们 P1 该抄什么
声明式配置 5 个 YAML：staff / shifts / positions / rules / calendar 我们的 org.json 直接照这个切分：人员 / 班次 / 岗位 / 规则 / 日历（不可用时间）
岗位有需求与技能 daily_need: 2 + required_skills: [CT_SCAN]， 人员侧写 skills: 与 night_eligible: 我们目前完全没有这个维度。认证部「不能查自己学院」就是一条反向技能约束， 必须先把"谁能干"建模成字段，不然规则写不出来
岗位分必排 / 可空 requirement: optional + priority:， 可选岗位人力不够就留空，校验时不计入配额检查 我们现在是"空着就告警"，没有"这格本来就可以空"的声明。 P1 必须补，否则每个机构都会被告警刷屏
校验器可进 CI medshift check 出问题清单、退出码 1，11 种错误码 （UNKNOWN_STAFF / SKILL_MISMATCH / POSITION_UNDERSTAFFED…） 我们的 _probe_random.py 已经是这个思路，但只测公平性。 P1 要补一个面向用户配置的 check，错误码化
锁定手工改动 求解器收 fixed=[Assignment(...)]；GUI 有「保留改动」复选框 和我们的 locked 完全一致 —— 验证了这个设计是行业共识，不用改
脱敏示例 examples/radiology/ 里姓名编号全是虚构占位符，含一整周排班数据 和我们的脱敏做法一致，照做即可
统计口径单一实现 stats.py 是"统计口径的唯一实现" 我们现在的统计散在 _load() / _campus_load() / load_stats() 三处， P1 应收敛到一处
它没有的、正好是我们的机会：① 不做换届交接；② 不做"上传你的空表、我只填格" （它导出的是自己固定的 Excel 版式）；③ 不区分包干制与轮值制（医院科室天然都是轮值制）。 这三条正是我们踩过坑、且广油场景真实需要的东西。

03三个正在被公认的价值点（2026 年新仓库里密集出现）

把两轮 20 组关键词的结果放一起看，star 数几乎全是 0，但描述里反复出现三个词。 这说明没人做成 ≠ 需求不存在，而是大家都在往同三个方向挤：

① 可解释 —— "为什么是他"

shiftlock（453 测试）、shift-scheduler、kanwarvig/shiftcraft-scheduler、ZHXY 悬停显示规则

四个独立项目都在做。我们已经有了（explain=true 逐格输出理由、前端悬停显示）， 这点不落后，甚至可以拿去当宣传点。

② 公平轮换 —— "凭什么总是他"

automated-rota-manager（MIT）、co-coach、PlayPositions、medshift 的 night_balance_weight

我们有 50 周实测（人均极差 1 件、标准差 0.24），但没有把这个数字写进 README 当卖点， 也没有"公平性报告"这个出口。medshift 有 stats 命令专门出这个 —— P1 要补。

③ 无解诊断 —— "排不出来时说清为什么"

shiftlock 的最小冲突集、shift-scheduler 的 explains every gap、hermes98761234 的 explains infeasibility

这是我们最大的短板。目前无解的表现是「某格空着 + 一条告警」，用户不知道是哪条规则卡死的、 更不知道改哪个数字能解开。P1/P2 明确要补。

04已落地：sort 链改写主代码（今日完成）

上一轮我从 Thomblin/duty-roster 学到的「规则写成一串 sort，而不是加权求和成一个代价分」， 今天已经进主代码。05_工作安排/engine/core/assigner.py：

# 旧：加权求和（四个常数，实测只有 1 个真在起作用）
COST_REPEAT_LAST_WEEK = 80
COST_ROTATED_ONCE = 30
COST_ROTATED_MORE = 12
COST_FLEX = 25
cost = 80*repeat + (30 + (total-1)*12) + 25*flex
sort by (cost, hash)

# 新：排序链（逐级比较，常数全部消失）
SORT_CHAIN = ["avoid_last_week", "least_loaded", "own_campus_first"]
rank = (
    1 if 上周做过这件活 else 0,
    历史累计 + 本周已派,
    0 if 能干这一列 else 1,
)
sort by (rank, hash)
验证项结果说明
第 11 周逐格对比18/18 相同，差异 0不违反「质检部结果逐格不变」门禁
50 周公平性（四项）与旧版全同人均极差 1 件 / 标准差 0.24 / 忙碌度极差 0.00 / 上周重复 11 次
_probe_random.py全绿可复现性、重摇、平局率、顺序偏差、长期公平 5 组全过
web/e2e.cjs43 项全过含导出表逐格比对
前端类型检查tsc 0 errorexplain 结构同步改造（cost:number → chain:[]）

顺带修掉的三个真问题：

  1. COST_FLEX 是死代码 —— slot_pool 已经按 can_do 过滤过， 自动路径永远触发不到。现在它是链上第 3 级，语义明确（"缺人了才让机动人员补"），不再是假装生效的常数。
  2. 轮值项线性膨胀会后期压过固定的 80 —— 50 周后轮值项约 642，上周回避（80）在学期末就废了。 sort 链里它永远排第 1 级，不会隐式失效。
  3. 「为什么是他」从"合计 110 分"变成逐级人话：
    上周没做过这件活 · 累计 1 件（历史 1 + 本周 0） · 本校区 —— 在第 2 级「累计件数」胜出（累计 1 件 vs 累计 2 件）
    如果每一级都并列，会明说「各项完全并列，按本周确定性序列裁决（可复现）」—— 不装作是规则决定的。
新增规则的代价从「回答这个常数该是多少、会不会把别的指标带坏」 变成「回答这条规则排第几」。排第几是有语义的，权重多少没有。 这正是 P1 配置化最需要的东西 —— 不然每接一个机构就要重新调一遍权重。

05判断修正：不是"没人做"，是"没人做成"

两轮加起来验证了 16 个仓库，star 分布是 0、0、0、1、1、1、3、4、6、13、15。 上一轮我据此说"空白区确认"，现在要打个折：

  • 仍然成立：没有 star 过百的同类项目；没有任何一个做的是「学生组织内部派活 + 跨机构版式 + 换届传承」这个组合。
  • 需要修正：star 低不代表需求不存在。medshift 一个人 133 个测试做到 v0.2 还发 exe， shiftlock 453 个测试 —— 这些是认真做的项目，只是没人知道。 推广难度比"空白区"三个字暗示的要大。
  • 对我们的直接含义：价值锚点必须钉死在它们不做、我们要做的三块 （换届交接包 / 上传空表只填格 / 包干制识别），而不是"我也能排班"。 秘书长那句"作用不大，部长自己分配也不难"，正是对"我也能排班"的正确评价。
