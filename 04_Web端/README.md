# 质检部周工作平台（Web 端）

把「质检部周工作自动化」技能做成了可视化网页：上传 Excel → 点几下 → 下载排版好的表。

## 怎么用

**双击 `启动.bat`** → 浏览器自动打开 <http://127.0.0.1:8765> → 用完关掉黑窗口。

> 不需要联网，数据全部在自己电脑。

### 改了网页源码 / 拉了新版本之后

**双击 `一键更新并启动.bat`**。它会自动关旧服务 → 重新构建前端 → 再启动，
省掉「忘记重新构建」和「旧进程占着端口」这两个坑。

> 只改 Excel 处理逻辑（`engine/`、`core/zjb.py`）也要重启服务，因为 Python 代码是启动时加载的。
> 只改前端（`web/src/`）必须走构建，否则浏览器拿到的还是旧 JS。
>
> 引擎已禁用静态资源缓存，构建完刷新页面（`Ctrl+F5`）就能看到最新界面。

## 四个步骤

| 步骤 | 做什么 | 说明 |
|---|---|---|
| 1 | 上传本周活动登记表 | 支持规划部发的总表，也支持已拆好的单校区表 |
| 2 | 按校区拆分 | 一次出官渡 + 西城两份；某校区无活动时出空白表 |
| 3 | 安排二级学院 | 自动标出「上周已安排」「本周主办」，勾选学院池即可 |
| 4 | 安排助理 | 填四个周末时段有空的人，自动匹配每活动 2 人 |

每一步的产物都能直接下载，文件名自动按规范命名：
`2026-2027学年第一学期第5周素质拓展活动登记表(官渡)（已安排二级学院）.xlsx`

安排完会自动出「表格预览 · 下载前体检」：网页里直接看 Excel 的真实排版（宋体、边框、标题合并都在），
并跑 7 项检查（文件可打开 / 表头识别 / 关键列齐全 / 标题合并 / 活动数 / 检查学院数 / OpenXML 结构校验），
全绿再下载，心里有底。

## 四个页面

- **本周工作**：主流程，四步走完
- **排班台账**：历史记录，可查看/删除某一周
- **数据看板**：各学院出动次数、每周工作量、校区分布，还能看到「从没排到过的学院」
- **使用说明**：内置操作手册（给干事看）——30 秒上手、每周节奏对照、三条铁律、8 条常见问题，
  以及**广油素拓政策速查**（学分模块、申报审批时点、登记表/名单时限、各部门职责、官方入口）

> 新人接手时，让他直接看「使用说明」页就够了。

## 导入历史表：两种表都能收

「导入历史表」不是要求先拆成校区表。系统会自动识别文件状态：

- **普通共享总表 / 校区表**：可以导入并归档活动；若表里尚无检查学院、助理，这两项会保持为空，不会伪造安排，也不会计入学院轮值。
- **已经安排完成的表**：会读取现成的检查学院和助理，补录完整台账。
- **腾讯文档 / WPS 在线共享表**：先导出或另存为本地 `.xlsx`，再拖入页面；系统不直接读取在线链接。

如果只是想处理本周、并不需要补历史，请使用「本周工作」上传总表，系统会继续执行拆分、安排和导出。

## 规则是自动守着的

- 每个活动 2 个检查学院
- 举办学院不检查自己（主办学院在界面上标红、不可选）
- 同一学院不连续两周（上周用过的标黄，选中会拦下来并给出替代建议）

万一你确认要强行安排，界面上有「仍要按当前选择写入」。

## 常见问题

**Q：改学院名单 / 换学期名怎么办？**
改 `engine/core/config.json` 里的 `colleges`、`term_name`，保存后重启服务。

**Q：台账在哪？**
默认和命令行技能共用 `C:\Users\HUAWEI\.workbuddy\skills\zhijianbu-weekly\data\ledger.json`，所以网页里排的班，命令行也能看到，反之亦然。

**Q：想重来怎么办？**
「排班台账」页右上角有「清空全部」，或按周删除。

**Q：格式会不会变？**
不会。字体（宋体 9 号 / 标题 24 号）、边框、居中、标题合并、列宽行高全部原样保留，只在表尾追加列。

**Q：写坏了能恢复吗？**
能。每次写入前自动生成一份 `xxx.bak.xlsx`（同目录，保留最近一份）；
写文件本身也是原子的（先写临时文件再替换），中途出错原文件分毫不动。

**Q：预览用的什么引擎？**
优先用开源工具 OfficeCLI 高保真渲染，没装或失败时自动回退内置渲染，功能都不受影响。
对比分析与选型理由见 [技术选型-OfficeCLI对比分析与优化方案.md](./技术选型-OfficeCLI对比分析与优化方案.md)。

**Q：双击 bat 时提示「不是内部或外部命令」或满屏乱码？**
这是 bat 文件被编辑器存成了 UTF-8，cmd 按 GBK 读就崩了。两个 bat 现在都已按 GBK + CRLF 保存，
**不要用记事本/VSCode 改完直接保存**——要改就告诉我，我用脚本重新生成。

**Q：为什么我刷新页面还是旧的？**
浏览器在复用缓存的 JS，或者服务进程还是旧的。按顺序排查：
1. `Ctrl + F5` 强制刷新（现在引擎已禁用缓存，正常情况下没必要了）；
2. 还不行就双击 **`一键更新并启动.bat`**，它会重新构建并重启服务；
3. 确认没同时开着开发模式（`npm run dev`）访问 5173 端口——那走的是源码热更新，跟 8765 是两套。

## 以后搬到服务器

这套东西本身就是标准的前后端结构，迁移分三步：

1. 把 `engine/` 整个目录放到服务器，装依赖：`pip install fastapi uvicorn python-multipart openpyxl`
2. 启动：`uvicorn main:app --host 0.0.0.0 --port 8765`（建议配 Nginx + HTTPS）
3. 前端打包时指定后端地址：在 `web/` 下新建 `.env.production`，写
   `VITE_API_BASE=https://你的服务器地址`，然后 `npm run build`

如果要在服务器上存台账而不是用本地那份，启动时加环境变量：
`ZJB_LEDGER=/data/ledger.json`
