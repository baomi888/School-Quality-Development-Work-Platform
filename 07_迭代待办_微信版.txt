【质检部工作自动化平台 · 后续优化/设计/迭代清单（给同事）】

平台定位（铁律）：只做机构内部派活 + 规划部/认证部的表处理；不碰教务系统、不替代到梦空间/i志愿、不代学生申报。

🔴 一、P0 安全合规（必须先做）
1. 撤销暴露的 GitHub PAT：对话里出现过 3 枚 fine-grained PAT，已暴露，去 GitHub 删除重写。
2. 强制改默认口令：05 默认口令 sutuo 仍是代码常量，文件不存在也放行；应改成"首次必须改、否则禁用管理层接口"。
3. 04↔05 跨服务调用鉴权：05 的 /api/plan 开放只读无来源校验，应加最小来源/内网限制。
4. 隐私回归扫描进 CI：现有靠人工 git grep 扫真名，应做成 CI 脚本，防真实姓名/花名册回流入库。

🟠 二、P1 架构 / 数据一致性 / 联动
1. 双端数据契约统一：04（周/校区/活动+检查学院+助理）与 05（按人 ledger + plan 网格）模型割裂，联动靠硬编码端口+HTTP。建议抽共享 schema，或让 04 同机直读 05 plan，并明确"第 N 周安排第 N-1 周活动"的对齐约定。
2. 配置集中化：端口、CORS、plan_url、前端 BASE 散落多处，建议统一配置。
3. iframe 双向通信：05 嵌 04 仅靠 /api/health 探活，无 postMessage 状态同步。
4. 联动自动触发：现在手动点"从安排台同步助理"；可加"05 提交后提示 04 同步"。目前回填是校区级（整周同校区同助理组），若需逐活动精确需扩模型。

🟠 三、P1 功能迭代（最实在的活，详见仓库 06_通用平台规划/规划部模块开发清单.md）
- 规划部 12 个候选模块（有规章依据+优先级）：催报与收件台账、负责人核对台、迟报漏报说明书生成、加分名单核对合包、学院报送质量看板、临时项目申报书 AI 预审、常规项目库查询、修改申请表生成、值班室模块、会议记录成稿、加分分值合规校验。
  👉 最短路径：先做 1 / 2 / 5（都小，且直接复用"活动汇总"已产出的数据：收件记录、负责人列、校验报告）。
- 认证部（rzb）真实轮值规则：回避硬过滤框架已搭，但缺 college+scope 真实数据，规则待把"已确认与待确认"落代码。
- 三原型补全（排班型/排期型/招募型），现仅派活型完善。
- 智能体编排层（04 的 agent.py 约 935 行，四段式闭环+七工具）：新交付，需评估成熟度、补测试、界定模型边界与降级。
- 历史归档在线预览：04 已有下载，缺 xlsx 在线预览。
- 导出模板化：换部门仍部分硬编码，目标"填一份配置零代码接新部门"。

🟡 四、P2 质量与测试
1. 无 CI：现有 _probe_*.py 是本地门禁，未接自动 CI。建议 GitHub Actions 跑这些 + 隐私 grep 扫描。
2. 缺 pytest 套件：_probe_* 是脚本式断言，建议迁移到 pytest + 覆盖率。
3. 旧 e2e 脚本未适配 ?dept=：e2e.cjs / ledgercheck.cjs 已知待办。
4. 前端无测试：04/05 仅 tsc 类型检查 + 手动。

🟡 五、P2 工程与部署
1. 无发布流水线：web_dist 靠本地手动 build；"免安装.zip" 手工打包。建议 build→打包→发布自动化。
2. 依赖锁版本：检查 requirements.txt / package.json 是否可复现。
3. 日志/可观测：统一 /health /ready + 结构化日志。

🟢 六、P3 体验与前端
1. 性能：04 引入 echarts 较大 chunk，可评估轻量图表/分包。
2. 移动端适配：小助理截图发群场景，工作台是否适配手机。
3. 可访问性：无 a11y 审计。

先收口 P0 安全（撤 PAT、改口令、隐私扫 CI），再把规划部模块 1/2/5 这"小而复用汇总数据"的三件做了；架构侧的"双端数据契约"和"联动自动触发"作为中长期重构，别和快速功能迭代混在一起。
