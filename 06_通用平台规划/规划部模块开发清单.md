## 一、本轮已交付：活动登记表汇总

**解决的手工劳动**：各二级学院／机构把单表交上来后，规划部逐个下载、逐个核对、再手工拼成一张总表。

**位置**

| 文件 | 作用 |
|---|---|
| `04_Web端/engine/core/merge.py` | 汇总内核（读取/清洗/去重/排序/校验/出表） |
| `04_Web端/engine/merge_tool.html` | 工具页（零构建，不依赖 `web_dist`） |
| `04_Web端/engine/main.py` | `POST /api/merge`、`GET /merge` |
| `04_Web端/engine/_probe_merge.py` | 内核回归门禁（70 项） |
| `04_Web端/engine/_probe_api_merge.py` | Web 端到端门禁（42 项） |

**产出四件套**（依据：注意事项第 47 条「需制作两个表格……表一发给宣传部（不包含活动对象为协会会员的活动），表二发给质检部（总表）」）

1. **总表**（表二 · 质检部）
2. **表一**（宣传部）—— 自动剔除「活动对象＝协会会员」的活动
3. **时间表**（《每周活动登记表时间》）—— 按活动时段展开（同日多时段自动拆行）
4. **汇总校验报告** —— 校验问题 / 来源追踪 / 疑似重复

**已落成校验项的规章依据**

| 校验项 | 依据 |
|---|---|
| 活动名称三段式（年份/届数＋机构/学院＋活动名），年份与届数不可同时存在 | 注意事项「活动名称」、「年份和届数不可以同时存在」 |
| 活动名称不能含引号 | 培训 PPT 第 6 页「活动名称不能加引号！」 |
| 活动级别取值与「院（系）级→院级」归一 | 注意事项「活动级别」 |
| 活动级别 ↔ 活动对象对应（校级↔全校学生、院级↔全院学生、协会培训↔协会会员且为校级） | 注意事项 + 培训 PPT 第 27 页 |
| 主办单位不得写到「××部门」 | 注意事项「主办单位」 |
| 项目类别只能三选一 | 注意事项「项目类别」 |
| 活动类型只能是临时/常规 | 注意事项「项目类型」 |
| 时间须细化到周几＋`00:00-00:00` | 注意事项「时间」 |
| 线上活动地点须有链接或邮箱 | 注意事项「地点」 |
| 联系方式须为 11 位手机号 | 注意事项「长号&短号」 |
| 加分分值须含数值（或写「累计服务时长」） | 培训 PPT 第 28 页、第 16 条 |
| 校区须为西城/官渡/光华 | 注意事项「校区」 |
| 所有符号用英文符号（顿号除外） | 助理培训 PPT 第 7 页 |
| 内容超出官方列宽（21 磅行高只放 1 行会被裁） | 官方《总表》列宽实测 + 注意事项「行高统一 21 磅」 |

**排序规则**（依据：注意事项「三．注意事项 → 活动排序」）
持续时间长的先排 → 只有一天的按周一至周日 → 同一天内按时间早晚。

**版式**（依据：注意事项「表格制作」＋官方《第4周活动登记表(总表).xlsx》实测标定）
标题宋体 24 号加粗、行高 30 磅且只描外框；正文宋体 9 号、行高 21 磅；仅内容区加边框；备注列红字。

**两条防错设计**（都不改变学校流程，只是不让工具犯错）

- **绝不跨周混表**：输入里混了不同周次时按周分组、各出一套产物并明确提示，而不是默默并成一张。
- **去重分级**：名称＋时间＋地点完全相同的自动合并并保留全部来源；仅同名的**只标记不自动删**，交回人工判断（依据：注意事项「需查看是否有重复的活动」）。

催报台账复用收件记录，负责人核对台复用总表的负责人列，质量看板复用校验报告的逐条问题。
一件活做三次不如一条线做一次。

## 三、明确不做

- **到梦空间 / i 志愿的职能**（面向学生的活动发布、报名、签到、学分）：已有成熟系统，重复造轮子没有意义。
- **代学生申报**：申报是主办方的责任，工具只做预审与提醒，不代替提交。
- **抓取教务/素拓系统**：本轮按「先只做合并」执行，不接触账号密码。若后续要做，
  需要先拿到系统的接入许可与页面结构，并且要能实测——写一个无法验证的爬虫脚本没有价值。
