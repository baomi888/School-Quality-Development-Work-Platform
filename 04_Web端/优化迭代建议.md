## 2. 仍可优化迭代的点（按优先级排序）

### P0 — 工程健壮性（低风险、高收益，建议下一步就做）

**2.1 缺 ErrorBoundary**
当前任一组件渲染崩溃 = 整页白屏，且无提示。建议加一个 `class ErrorBoundary` 包住 `<App>`，崩了显示「出错了 + 重新加载」的兜底卡片，而不是白屏。

**2.2 缺自动化验收门禁**
现在靠手动截图排查。建议把现有的 `_shots/diag.js`（查 404 / console error / 横向溢出）+ `_shots/responsive.js`（多宽度溢出）接成 `npm run verify`，构建后自动跑，任一不达标就拦截。这样以后「改了没坏」可证明。

### P1 — 代码结构（可维护性）

**2.3 `Work.tsx` 单体过大（约 716 行）**
建议拆成：`useWorkflow` / `usePreview` / `useDiagnose` 三个 hooks + `StepBar` / `CollegePool` / `PreviewPanel` / `DiagnoseList` 子组件。单文件过大会让后续改动风险高、diff 难读。

**2.4 `styles.css` 单体过大（约 678 行）**
建议按域拆分：`tokens.css`（变量）/ `base.css` / `layout.css` / `components.css` / `pages.css`，用 `@import` 或 Vite 合并。降低误改风险。

**2.5 无路由，Work/Ledger/Guide 同在主 bundle**
ECharts 已懒加载，但 `LedgerView`、`Guide` 仍在首屏 180KB 里。建议加 `react-router` 或手写 `lazy()`，把这两个页也懒加载，首屏再瘦一圈。

### P1 — 设计保真度（对齐 mockup）

**2.6 空状态缺 mockup 元素**
风格预览 `03-瑞士理性.html` 的首屏有 `01/02/03/04` 编号步骤卡 + 表格 + 读数条；实装空状态只有一句话。建议补齐编号步骤卡，让首屏就有「下一步做什么」的引导，也更贴近设计稿。

**2.7 顶栏布局与 mockup 基准有出入**
mockup 是「左品牌 / 右导航」基线；当前是「品牌 + 时间戳 + 标签页」挤在左侧、标签页靠 `margin-left:auto` 推到右边。建议把构建时间戳移到品牌副标题行或页脚，让导航回到干净的右对齐，顶栏更克制。

**2.8 深色模式打磨**
- accent `#ff6a5a` 在深色长文里偏亮，建议降到 `#ff7a6a` 并加 1px 边界。
- 表格 / 卡片边界在深色下对比不足，需补 `--line` 在深色的具体值。
- 实测无头 Chromium 默认 `prefers-color-scheme: dark`，顶栏 accent 会显示 `#ff6a5a`——这是预期，不是 bug，但手动切换 + 打磨值得做。

### P2 — 体验细节

**2.9 chip 缺 `aria-pressed`**：标签页的 `role="tab"`/`aria-selected` 已加，但学院选择 chip 还没 `aria-pressed`，读屏用户无法感知选中态。

**2.10 手动主题切换**：目前只能跟系统 `prefers-color-scheme`，无手动开关。可加顶栏太阳/月亮按钮，方便演示和弱光环境。

**2.11 构建时间戳在 ≤900px 隐藏**（避免拥挤），但移动端反而最该显示版本——建议移动端移到页脚常驻。
