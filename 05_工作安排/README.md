# 学生组织工作安排台

> 一句话：**给高校学生组织用的工作安排工具。排一遍，不满意随手改，改完导出成你们部门自己的表。**

起因是广东石油化工学院校素质拓展中心质检部的真实需求：每周 9 件活、17 名助理、两个校区，
部长手排要半小时，还总被问「为什么又是我」。这个工具把这件事变成点一下按钮。

**它要解决的问题只有一个：机构内部，这个活派给哪个干部去干。**

---

## 边界：我们不做什么

学校里已经有**到梦空间**和 **i 志愿**，它们管的是「学生参加什么活动、拿多少学分」。
那是面向全体学生的，做得很好，我们不碰。

本工具管的是**机构内部的工作分工**——谁去现场检查、谁写这篇推文、谁这周值班。
两者互补，不冲突，也不重复造轮子。

```bash

pip install fastapi uvicorn openpyxl

# 启动（Windows 双击 启动.bat 也行）
```

## 职责边界：谁会被派到活

> 默认规则：**部长给助理派活，部长/副部长只监督、不接活。**

- 派活池只收 `role=assist` 且 `active=true` 的人
- 领导层即使被手动锁定也会被忽略（界面上单独一块，标题写明「只监督不派活」）
- 需要领导拍板的活**照派给助理执行**，但会进「待确认」清单提醒签字

如果你的机构不是这个规矩（比如副部长也要干活），在人员池里把角色改掉即可，
不需要改代码。

## 核心设计

### 四个原型，一套内核

不同机构的「工作安排」长得不一样，但收敛成四类：

| 原型 | 问的问题 | 典型部门 | 槽位维度 |
|---|---|---|---|
| 派活型 | 这件活谁去干 | 质检部、认证部、考核部 | 任务 × 校区 |
| 排班型 | 哪天哪个时段谁在岗 | 综合部、自律部 | 日期 × 节次 |
| 排期型 | 谁在什么 deadline 前交什么 | 宣传部、新媒体中心 | 稿件 × 发布日期 |
| 招募型 | 活动需要多少人、谁报名 | 青协行动部 | 场次 × 名额 |

它们共用同一套内核，差别只在五个可配置项：**人员池 / 任务清单 / 槽位维度 / 约束规则 / 输出模板**。
当前版本实现了「派活型」，其余三类是同一内核换槽位维度的事。

### 为什么不用随机数

第一版用 `random.Random(seed)` 打平局。实测发现三个问题，已全部重写：

| 问题 | 实测数据 |
|---|---|
| `seed` 不传时按系统时间播种 | 同一批输入跑 5 次出 5 张不同的表，事后无法还原 |
| 平局率过高 | 首周 83% 的格纯靠随机定；换个种子 89% 的格会变 |
| 遍历顺序引入系统性偏差 | 18 格派给 17 人时，「多干一件」永远落在清单最后一件活（末位活 1.61 件 vs 其他 1.05 件） |

现在改为**确定性裁决**：

- 平局用 `sha256(周次|重摇次数|人员id)` 比较，随周次变化保证长期均匀
- 待分配的格按稳定哈希乱序，「哪件活承担多出来的一件」每周轮换
- **不再依赖 `random` 模块：同样的输入，永远同样的输出**

结果是：任何人拿着周次和重摇次数都能复现同一张表，
面对「为什么是他」的质疑时给得出答案，而不是一句「系统随机的」。

### 公平性实测

连续排 50 周（`python _probe_random.py`，已固化为回归测试）：

| 指标 | 重写前 | 重写后 |
|---|---|---|
| 各活「负责人忙碌度」极差 | ~1.1 | **0.20** |
| 50 周人均累计件数极差 | 4 件 | **1 件** |
| 三校区人均 | 西城 54.6 / 官渡 51.6 | 西城 52.9 / 官渡 53.0 / 光华 53.0 |
| 单周最大负载 | ≤2 件 | ≤2 件 |

顺带修掉的一个隐藏不公：光华校区 2 人的主校区被归到官渡，
导致他们被官渡列优先吸走、西城 8 人长期多扛一件活。
改为按 `can_do` 判定跨校区代价后，两列对他们等价，去哪边由负载决定，长期自动均衡。

## 派活规则（按优先级）

| 优先级 | 规则 |
|---|---|
| 1 | 锁定项不动 —— 手动纠正过的，重摇时保留 |
| 2 | 只派助理 —— 领导层不进候选池 |
| 3 | 轮值优先 —— 历史累计少的人优先 |
| 4 | 主校区优先 —— 机动人员只在缺人时补 |
| 5 | 负载均衡 —— 本周已派的人代价递增 |
| 6 | 防重复 —— 避开「同一件活紧邻上周给了同一个人」 |

> 防重复只避「紧邻上周」：如果永久回避做过某件事的人，
> 会出现固定几个人无限循环、其余人永远轮不到的情况。

**不假装完美**：哪一格空着、谁被连派两件、实在避不开的重复，
都会在最上方如实列出来，不藏。

## 隐私：真实名单不会进仓库

本项目开源，所以**代码里不能出现任何真实同学姓名**。

- `models.py` 的 `DEFAULT_PEOPLE` 是脱敏示例（「示例·西城甲」这类占位名）

如果你 fork 后要二次开发，请保持这条红线。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| GET | `/api/bootstrap` | 一次拉齐人员/任务/台账 |
| POST | `/api/people` | 保存人员池 |
| POST | `/api/tasks` | 保存任务池 |
| POST | `/api/assign` | 分配（支持 `week` / `seed` / `locked` / `explain`） |
| POST | `/api/commit` | 存入台账 |
| POST | `/api/clear-week` | 撤销某周台账 |
| POST | `/api/export` | 导出 xlsx |

`explain=true` 时返回每一格的分配理由（选中者代价明细、候选人数、
并列人数、次优候选人差多少），用于回答「为什么是他」。

## 已知不足

诚实列在这里，不藏：

- **只实现了「派活型」**——排班型/排期型/招募型还没做，需要换槽位维度
- **导出模板是硬编码的**——照着质检部官方样表逐格复刻，换一个部门就得改代码。
  通用化的最大工程量在这里，理想形态是「上传空表 → 只填格子」
- **不支持临时请假**——某人这周没空，只能从人员池停用
- **单人进程，无账号体系**——适合部门内部用，不适合放公网
- **校区/角色写在模型里**——新增校区或角色要改 `models.py`
- **值班表是静态导入**（`duty.py`），学期变了要改文件，没做 UI 编辑
