06 · 通用平台规划

从质检部工具到全校通用平台
落地方案

回答一个问题：接下来十二个月，先做哪件事、后做哪件事， 每一步做完凭什么算做完了。所有技术判断都附带实测数据，不靠估计。

方案日期 2026-10-09 发起人 冯靖豪（校素拓质检部副部长） 依据 3 份实测探针 · 2 轮调研 周期 四期 · 约 12 个月 · 对齐换届季
先说结论

不要重写，要抽配置。

你现在手上有 2120 行跑得通的代码、43 项 API 断言、三份回归探针。 它的内核（人员池 + 确定性裁决 + 台账 + 导出）是对的， 错的只是"西城/官渡""质检部第 X 周"这些写死的字面量。 通用化等于把这些字面量搬到一个 org.json 里，代码一行不删。

方案分四期，第 0 期本周就能做完（1~2 天，产出可对外发布的东西， 推广和宣传视频需要它）。最后一期卡在明年 6 月换届之前—— 这是全校学生组织唯一的硬时间窗，错过要等一年。

最大的技术风险——"每个机构版式不同，怎么导出"——今晚已经实测解除， 详见第 04 节。

01现在站在哪

先把家底点清楚。通用化不是从零开始，是决定哪些留下、哪些推倒。

资产规模判定理由
确定性裁决内核
assigner.py		374 行保留 已不用 random。50 周模拟人均累计极差 1 件（理论下界）， 各活忙碌度极差 0.20。这是整个平台最值钱的部分。
JSON 持久化
models.py		236 行保留 数据全是能看懂的 JSON，脱离平台也能用——这是对抗"换届无人接手"的唯一解药。
API 层
main.py		348 行改造 单机构单租户，所有路径假设"只有质检部一个机构"。要加机构维度。
前端工作台
App.tsx		886 行改造 type Campus='西城'|'官渡' 是字面量类型，写死了。要改成按配置渲染。
导出器
exporter.py		123 行替换 CAMPUS_COL={"西城":2,"官渡":4}、ASSIST_BLOCK_ROW=14 全是硬编码列号。这是通用化最难的一块，也是今晚刚验证完的一块。
默认种子
DEFAULT_PEOPLE		21 人已完成 已全量脱敏为"示例·西城甲"。engine/data/ 已进 .gitignore。 开源红线已解除。

一个反直觉的判断：改得最多的是导出器（123 行），但它恰恰是 风险最低的——因为新版不需要"改对"，只需要"不改坏"。 真正的风险在前端（886 行按配置渲染），那才是工作量大头。方案把前端放在第 2 期， 就是为了让第 1 期先用最小的改造验证内核抽象是对的。

02目标架构：一个内核 + 三层配置

通用化的全部秘密，是把四维差异收进一个模型：行维度 × 列维度 → 一格。

先看四种原型在这个模型下长什么样：

原型行维度列维度每格样本
派活型任务清单（9 件活）校区（西城 / 官渡）1~N 人你的质检部表
排班型节次（1-2 / 3-4…）日期（周一 ~ 周五）1 人秘书处值班表
排期型稿件清单角色（撰稿 / 审核）1 人宣传部、青媒
招募型场次清单名额（1 号位 / 2 号位…）1 人青协活动招募

派活型的"活"是行、校区是列；排班型的"节次"是行、日期是列。 两者是同一个形状，区别只在维度从哪来。连常州工学院样本里那个 "承办人 / 负责人"两级责任，也只是把列维度换成"角色轴"而已。

于是机构之间全部的差异，可以收进一份配置：

{
  "org": "校素拓质检部",
  "slot_dims": [                       // 列维度：0~N 个
    { "key": "校区", "values": ["西城", "官渡"], "pool_by": "can_do" }
  ],
  "row_source": "tasks",               // 行维度：来自任务清单
  "capacity": { "min": 1, "max": 2 },  // 每格容量（搭档制）
  "rules": {
    "max_per_week": 2,
    "avoid_repeat_last_week": true,
    "cross_dim_cost": 25               // 跨校区/跨维度机动代价
  },
  "template": "质检部官方表.xlsx",     // 上传的空表，平台只填格
  "map": {                             // 占位符 → 数据源
    "任务.%d": "row.name",
    "西城.%d": "cell.西城",
    "官渡.%d": "cell.官渡"
  }
}

换成排班型，只需要改 slot_dims 和 row_source，代码一行不动：

{
  "org": "某学院秘书处",
  "slot_dims": [
    { "key": "日期", "values": ["周一","周二","周三","周四","周五"] },
    { "key": "节次", "values": ["第1-2节","第3-4节","第5-6节","第7-8节"], "axis": "row" }
  ],
  "row_source": "dim:节次",
  "capacity": { "min": 1, "max": 1 },
  "rules": { "max_per_day": 1, "avoid_back_to_back": true }
}

为什么不再写一版：如果给每个机构写一套代码，122 个机构就是 122 份维护负担， 你大四之后没人接得住。配置化的意义不是优雅，是让第二个会改的人改得动。

03四期路线

每一期都有三样东西：做完的标志（能演示给别人看）、 验收门禁（跑脚本，不靠感觉）、回滚点（做砸了退到哪）。 十二个月对齐到明年 6 月换届季。

PHASE 0 冻结 v1，做出能给别人看的东西 本周 · 1~2 天

这一期不写新功能。目的是把现有成果固化成一个能对外发布的状态—— 你要推广、要拍宣传视频，首先得有一个别人能下载、能双击跑起来的东西。

做
  • git init 建仓库，打 tag v1.0
  • 逐项自查 git status，确认 engine/data/ 下一个文件都不在
  • 用免安装打包脚本出一份 zip（上次已跑通，约 45.6 MB），换一台没装 Python 的电脑验证双击能起
  • README 补一段"给部长看的 30 秒说明"：这是什么、解决什么、怎么跑
产出
可发布的 v1.0 zip + GitHub 仓库（公开）
门禁
干净机器上双击 启动.bat → 浏览器打开 → 点分配 → 导出 xlsx，全程无报错
回滚
无风险——全是打包与文档，不碰逻辑代码
为什么先做这个推广需要物料，访谈需要"你看我已经做出来一个了"作为敲门砖。 拿不出能跑的东西去聊，对方只会当你是来征求意见的；拿得出，对方才会认真给你看原件。
PHASE 1 内核配置化 + 问出决策规则 10 月下旬 ~ 11 月中 · 约 3 周

两条线并行：一条是找人聊（不依赖代码），一条是改代码（不依赖聊的结果）。 这样即使访谈泡汤，代码这边也不空转。

代码线
  • models.py：把 CAMPUSES=["西城","官渡"] 换成从 org.json 读 slot_dims
  • assigner.py：slot 从"校区字符串"泛化为"维度值元组"； _cost 里的跨校区判断改为跨维度判断
  • _probe_random.py：扩展成能跑任意 org.json 的公平性回归
访谈线
找 3 个原型不同的部门各聊 30 分钟。重心不是要表（版式已有 6 份样本）， 是问规则：为什么派他不派她、同一件活能不能连做、有人请假怎么补、谁说了算
产出
一份 org.json schema + 跑通两个不同配置的引擎 + 一页"决策规则清单"
门禁
  • 同一套代码，加载质检部配置跑出的结果与改造前逐格一致（这是最硬的回归）
  • 加载排班型配置也能排出来，且公平性探针全绿
  • web/e2e.cjs 43 项不退化
回滚
保留 v1.0 tag，配置化失败就退回，损失 3 周但不影响已发布版本
这一期最大的坑不要为了让排班型跑通，就去动质检部的默认行为。 判断标准只有一条：质检部的结果必须逐格不变。如果变了，说明抽象错了，不是配置错了。
PHASE 2 模板化导出 + 接入第二个机构 11 月中 ~ 12 月中 · 约 4 周

这一期是整个方案的成败点：能不能接住第二个机构。 接住了，122 个机构只是重复劳动；接不住，前面全是自嗨。

做
  • 导出器重写为"上传空表 → 扫占位符 → 只填格 → 另存"（技术路线今晚已实测）
  • 模板库：每个机构存一份自己的空表，附占位符说明
  • 页面加"机构切换"：下拉选机构，加载对应 org.json + 模板
  • 第二个机构真跑一周——不能只在自己电脑上跑通，要让它实际用起来
产出
双机构可用的版本 + 2 套模板 + 一份"新机构接入指南"
门禁
  • _probe_template.py 全绿（样式 / 合并 / 列宽 / 冻结 / 条件格式 / 公式 / 图表 逐项断言）
  • 第二个机构导出的表，能被该机构的部长认可是他们的表（不是"差不多"）
  • 新机构接入全程 ≤ 30 分钟，且不需要改代码
回滚
导出器新旧并存，用配置开关切换；老机构继续走旧路径
接入时间就是验收标准"≤ 30 分钟且不需要改代码"这条必须量化。 如果需要你改代码才能接入，说明配置化是假的，这时候应该停下来重做第 1 期， 而不是硬接第二个机构——硬接出来的第三个、第四个会更痛。
PHASE 3 素拓体系横向复制 12 月 ~ 次年 3 月 · 含寒假

从 2 个机构扩到 20+ 个。从哪里扩是有讲究的——不是挑容易的，是挑同构的。

顺序
  • 校素拓 6 部门（认证 / 质检 / 规划 / 宣传 / 竞赛 / 综合）—— 你有话语权，抬头不见低头见，规则问得到
  • 19 个院素拓质检部——与你同构，一份模板复用 19 次， 这是性价比最高的一段
  • 再往外：青协、学生会、分团委
做
批量接入 + 收集反馈 + 补齐缺失的规则（一定会有你没想到的）
产出
20+ 机构在用 + 规则库沉淀 + 第一批真实使用数据
门禁
每个新机构接入时间随数量递减（第 20 个应显著快于第 5 个）。 如果不变快，说明模板复用没做对
回滚
机构级隔离：一个机构的配置坏了不影响其他机构
寒假是真实风险：12 月到 3 月中间隔着寒假，学生组织基本停摆。 计划里要把 1~2 月当成不可用时间，不要排依赖别人的任务， 只排你能独立完成的（写代码、写文档、整理模板）。
PHASE 4 换届交接包 + 全校推广 次年 3 月 ~ 6 月 · 卡换届前

这一期决定了这个平台是活过一年还是随你毕业一起消失。 也是全网同类工具唯一没人做的一块。

做
  • 一键导出交接包：今年谁干过什么、各干几次、岗位说明书、历史台账、模板
  • 培养第二个会改的人（这比写代码重要）——让他独立完成一次新机构接入
  • 宣传视频：素材用第 04 节的实测对比表，比任何功能演示都有说服力
  • 向校团委 / 院团委正式汇报，争取一个"官方推荐"的身份
产出
交接包生成器 + 第二个维护者 + 宣传视频 + 官方背书（争取）
门禁
让你完全不参与，第二个人能在 30 分钟内接入一个新机构并完成一次周排班。 做不到，这个平台就没有越过换届这道坎
回滚
—
时间窗只有一次换届一般在 6 月。交接包必须在换届之前做好， 因为换届那一周所有部长都在换人，交接包的价值在"旧部长把东西交给新部长"的那一刻。 错过要等一整年。

04三个已实测的技术决策

方案里所有"该不该"的问题，都用探针跑数据回答，不靠经验判断。

决策一：确定性裁决取代随机

你问的"是否存在伪随机"，实测下来比伪随机更糟——是系统性不公平。

指标修复前修复后
seed=null 可复现性5 次 5 种结果完全一致
各活忙碌度极差1.1（末位活被压双份）0.20
50 周人均累计极差4 件1 件（理论下界）
三校区人均件数54.6 / 51.6（差 12%）52.9 / 53.0 / 53.0

修复前最要命的一条：18 格派 17 人，每周必有 1 人干双份， 而这个人被任务顺序钉死在最后一件活上。随机只决定"谁是倒霉蛋"， "一定有人倒霉"是确定性的。

决策二：双引擎，不二选一

指标贪心（现行）CP-SAT 求解器
单周耗时0.4 ms12~17 ms
50 周人均极差1 件1 件
50 周"上周同活重复"11 次0 次
加一条新规则的成本改代价函数 + 维护状态4 行约束

公平性打平（1 件是理论下界）。差距在"多规则同时满足"： 贪心挨个让步，"上周同活回避"50 周被牺牲 11 次，求解器一次没破。 规则越多差距越大，而适配 122 个机构恰恰意味着规则越来越多。

所以：默认贪心（零依赖、毫秒级、已过 43 项 e2e，保住"双击就能跑"的免安装优势）， 规则复杂时切 CP-SAT（可选依赖 ortools，没装自动降级）。

一个必须记住的教训：第一版求解器目标函数只压了"最大值"没压"极差"， 大机构场景下 50 周人均极差变成 2、标准差 0.71，反而比贪心差。 改成压极差才打平。求解器再强，目标函数写错照样不公平。

决策三：模板化导出（今晚刚验证）

这是通用化最难的一块：每个机构版式不同，不可能为每个机构写一套导出代码。 方案是让机构上传自己的空表，平台只往格子里填字。 风险在于 openpyxl 的"读进来—改—存回去"会不会把原表样式弄坏。实测结果：

项目结果说明
占位符替换（单元格）保住{{部门}}{{周次}} 正常替换
占位符替换（工作表标签名）保住今晚实测抓到的 bug：只扫单元格会漏掉 sheet 名里的 {{周次}}
合并单元格保住A1:D1 标题合并完好
字体 / 字号 / 加粗 / 居中保住宋体 16 加粗居中、行高 30 全部保留
列宽 / 行高保住—
底色 / 边框保住表头底色 D9E2F3、数据区细边框完好
冻结窗格保住—
条件格式保住空值标黄规则 B2:F5 完好
公式保住=IF(C2="","",C2-TODAY()) 未被破坏
图表保住往返后重新读回仍在
未填的占位符自动清空不会在表里留下 {{xxx}} 残迹

这意味着什么：机构上传的表长什么样，导出的表就长什么样， 平台只负责填字。你被部长拿官方样表质问一次的场景，不会再重演 122 次。

05验收门禁：每次改动跑这三个

所有验收都做成非零退出码的脚本，可以挂在提交前自动跑。 不要靠"我点了几下没问题"——你上次那个顺序偏差 bug，就是点几下看不出来的。

脚本耗时管什么
_probe_random.py秒级 可复现性、平局裁决均匀性、顺序偏差、50 周公平性。纯 Python，无依赖
_probe_template.py秒级 模板导出逐项样式断言（第 04 节那张表就是它的输出）
web/e2e.cjs分钟级 API 43 项，含导出表与官方样表逐格比对
web/ledgercheck.cjs分钟级 台账持久化 12 项——长期公平全靠它

加断言的方法论：不要只测"某个种子下结果对不对"。 上次 e2e 跑了 12 周压测没抓到负载计价 bug，就是因为随机种子恰好没触发。 要写不利场景探针——比如"同一周已有台账时重复分配 5 次"， 专门往最容易出问题的地方撞。

06风险登记表

风险概率影响对策与触发条件
访谈拿不到原件中中 已有 6 份他校公开样本可兜底版式。触发：两周内一份都拿不到 → 暂停访谈线，全用公开样本推进第 1 期，把访谈挪到第 3 期
第二个机构接不进来中高 这是方案的证伪点。触发：接入耗时 > 30 分钟或需要改代码 → 停在第 2 期，回头重做抽象，不要硬接
你大四后无人维护高高 第 4 期的硬门禁就是为此设的。提前：第 1 期就开始带人， 不要等到第 4 期才开始找

真实姓名泄漏到公开仓库低极高 已脱敏 + .gitignore 排除 engine/data/。 每次提交前必查 git status --short engine/data/ 须为空
寒假停摆导致第 3 期延期高中 寒假只排能独立完成的任务（写代码 / 写文档 / 整理模板）， 不排依赖他人配合的接入工作

07本周就能做的五件事

  1. 建仓库、打 v1.0 tag——提交前先跑一遍 git status --short engine/data/， 必须为空。这是唯一的不可逆风险，先堵死
  2. 出一份免安装 zip，换台电脑验证——脚本上次已跑通，重跑一遍即可
  3. 约第一个访谈对象——推荐院素拓质检部（同构，最容易）， 只问三件事：你怎么排的、为什么派他、排错了谁找你麻烦
  4. 把 _probe_template.py 收进验收脚本——它今晚刚抓到一个真 bug （sheet 名占位符漏替换），说明它有用
  5. 开始物色第二个维护者——不要等到明年 6 月。现在就找一个大一的， 让他跟着你做第 1 期，他会是你毕业后这个平台还活着的唯一理由

08关于宣传视频

你提到要做视频推广。最有力的一段素材不是功能演示， 而是第 04 节那三张对比表——尤其是"顺序偏差"那一条：

"改之前，每周一定有一个人干双份，而且这个人永远是最后一件活的负责人。 我们以为是随机的，跑了 50 周模拟才发现：随机只决定谁是倒霉蛋， 一定有人倒霉是代码写死的。"

这段话的说服力在于它承认了错误。展示一个工具多好用，别人只会觉得"还行"； 展示你如何发现自己做错了、怎么量化它、怎么修好的，别人才会相信这个东西是真被用过的。

另外建议视频里明确说一句定位：不做第二课堂，不做活动报名。 学校已经有到梦空间和 i 志愿，任何"我们也能发活动"的表述都会让人以为你要抢地盘。 一句话讲清——"到梦空间管学生参加活动，我们管机构内部这个活派给哪个干部"。
